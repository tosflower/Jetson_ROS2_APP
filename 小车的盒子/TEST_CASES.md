# App 真机测试用例

## TC-007：高德地图定位与后台传感器发布

1. 启动 `rosbridge_websocket`，确认 Jetson 的 `9090` 正在监听；Phone Gateway 可同时保持在 `8080`。
2. 将 `.env.example` 复制为 `.env.local`，填写有效的高德 Web JS API Key 和安全密钥，重启 Metro，并确保手机能访问互联网。
3. 进入 App 的“地图”页，不进行额外点击；App 应自动请求前台定位和运动传感器权限，并自动连接 rosbridge。
4. 地图应显示高德底图，首次 GPS 到达后定位到当前位置，显示车辆方向标记和 GPS 精度圆；页面不显示传感器终端、消息列表或启停按钮。
5. 原地转动手机，车辆标记应随 `/phone/heading` 顺时针旋转；手机顶部朝北、东、南、西时应分别接近 0°、90°、180°、270°。
6. 在 ROS 2 端分别执行 `ros2 topic echo /phone/gps`、`ros2 topic echo /phone/heading`、`ros2 topic echo /phone/imu`、`ros2 topic echo /phone/magnetic_field`，核对类型为 `NavSatFix`、`Float64`、`Imu`、`MagneticField`。
7. 用 `ros2 topic hz` 核对 GPS 不超过 2 Hz、航向不超过 5 Hz、IMU 约 25 Hz、磁力计约 10 Hz；用 `ros2 topic info --verbose` 确认每个 Topic 只有一个 App 发布者。
8. 关闭 rosbridge 后地图定位与朝向仍应更新；重启 rosbridge 后四个 Topic 自动恢复发布，不得增加重复传感器监听器。
9. 将 App 切到后台后传感器暂停；回到前台后地图与 Topic 自动恢复，频率不得加倍。Phone Gateway 的 `8080` 功能保持正常。
10. 关闭手机互联网但保留与 Jetson 的局域网连接时，ROS Topic 应继续发布；高德底图无法加载或更新时应显示可读提示。

自动检查：`npx tsc --noEmit`、`npm run lint`、`node --test services/rosbridge/*.test.cjs services/phone-sensors/*.test.cjs`。

## TC-004：平板旋转与布局

1. 安装包含新方向配置的 APK，打开 Android 系统“自动旋转”。分别在登录页、启动页、配置表单、终端页、图像页和设置页旋转设备。
2. 横屏和竖屏均应正常布局，顶部导航、底部标签和输入框可操作，内容不会被刘海或系统导航遮挡；较短窗口可以滚动。
3. 在表单输入内容、启动任务、选择终端后连续旋转五次。输入、登录状态、所选终端和运行任务应保留，网关不应重新连接。
4. 图像页在足够宽的窗口左右分栏；窄屏和较大系统字体下纵向排列。放大系统字体后按钮文字仍可读。

## TC-005：全屏图像与手势

1. 订阅持续发布的图像，轻点预览进入全屏。确认画面比例正确、帧持续更新、话题与 FPS 可读，网关没有新增或重建图像订阅。
2. 双指放大到最大、缩小到最小；范围应为 1–4 倍。放大后向四边拖动，不能把整张图像拖出可视区域；1 倍时图像居中。
3. 用双击及底部缩放/还原按钮操作，再从双指缩放切换为单指拖动，确认画面不会突然跳跃。
4. 放大并拖动后旋转设备，图像重新适应新窗口，不应变形或消失，控制条和“完成”可点击。
5. 点击“完成”和 Android 返回键各退出一次，确认返回原话题、预览继续更新；重复进出五次，不出现重复加载回执或订阅。
6. 停止图像发布，最后一帧应保留且仍能放大；断开网关时应显示离线提示。尚未收到第一帧时打开全屏应显示等待状态，第一帧到达后自动出现。
7. 本项需要 Android 真机验证原生绘制、手势及连接连续性，Node 单元测试不能替代。

## TC-006：外观与应用图标

1. 在设置页切换浅色/深色，检查所有页面、底部标签、表单与按钮立即更新；白色主按钮文字在两种模式下清晰可读。
2. 外观切换后登录状态、运行任务与终端不应重置；重启 App 后保留所选外观。
3. 安装新 APK，检查桌面和应用列表显示提供的机器人图标。支持更换图标形状的启动器上确认机器人主体完整。

## TC-002：Android 连续图像切换稳定性

- 重新构建并安装包含 `BufferedImage` 的 APK，保持与旧版相同网关和图像源。
- 对准静止场景观察至少 60 秒，再移动相机；记录 FPS、是否闪黑，以及是否出现明显延迟。
- 暂停网关图像推送后，最后一帧应保留；恢复推送后应继续显示新画面。
- 若仍然明暗交替，同时对比源图像是否也变暗，记录安卓型号、系统版本和闪烁时刻。
- 此用例必须在 Android 真机执行；状态逻辑测试不能证明原生绘制无闪烁。

## TC-001：安卓连接、分页和图像话题选择

**目的**：验证手机 App 可通过当前局域网连接 Jetson 网关，并正确显示 WebSocket 推送的 JPEG 图像。

**前置条件**：

- 安卓手机或鸿蒙兼容设备与 Jetson 处于同一局域网。
- Jetson 网关服务已启动，且 WebSocket 地址为 `ws://<Jetson IP>:8080/ws/mobile`。
- 已使用 Expo Go 或新版 APK 打开本项目。

**步骤与预期结果**：

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 在“Jetson 网关地址”中填写 `<Jetson IP>:8080`，例如 `172.20.10.2:8080`。 | 输入内容可见，且不会被自动修改。 |
| 2 | 点击“连接网关”。 | 状态短暂显示“连接中”，成功后显示“连接成功”。 |
| 3 | 进入下一页。 | 显示两个默认任务、自定义文件、终端、图像和报告入口。 |
| 4 | 运行发布图像的任务，进入图像页。 | 列表自动出现 Image/CompressedImage 话题，并显示类型和发布者数量。 |
| 5 | 选择话题。 | 画面与 FPS 更新；切换话题后不再显示旧话题的帧。 |
| 6 | 断开 Jetson 网关服务或填写不可达地址后再次连接。 | 状态显示“错误”，并提示检查热点、IP 地址和端口。 |

**通过标准**：完成步骤 1 至 5，画面稳定显示且 FPS 持续更新；步骤 6 能给出明确错误提示。

**记录项**：测试日期、安卓/鸿蒙型号与版本、Jetson IP、实际 FPS、是否通过、异常截图。

## TC-003：手机终端与 Debug 输出

1. 在终端页输入绝对工作目录、环境脚本和 `ros2 launch 包名 文件.launch.py`，执行后应显示 cwd、source、命令、PID 和 ROS 日志。
2. Python 程序连续打印信息时，输出应在约 0.5 秒内刷新；暂停自动滚动后可以查看和复制旧日志。
3. 点击停止后应显示停止过程和退出码，并确认 Jetson 上对应 launch 子进程已退出。
4. 输入 `cd`、`&&`、管道、重定向、任意系统命令或不存在的文件，应拒绝执行并显示原因。

## 自定义命令实机验收

1. 平板连接新版网关；输入不存在或相对目录，应提示错误且无法校验启动。
2. 输入实际 Jetson 目录并确认，核对列表；输入带空格路径的 Python 文件和参数，校验后启动，检查日志及图像。
3. 修改目录/命令/环境脚本后，启动按钮应失效，必须重新校验。
4. 分别启动本地 launch、ROS 包 launch、`ros2 run` 节点；为不同工作区指定对应 `install/setup.bash`。
5. 运行一个持续输出的节点，另一客户端尝试启动应被拒绝；停止后确认相关 ROS 子节点消失。
6. 立即报错的 Python 文件应记录失败且不能加入预设；成功记录可命名保存。重启 App/网关后预设和历史仍在。
7. 载入预设后确认目录并执行；移动/删除目标文件后重新执行，应在校验/启动时被拒绝。删除预设不应删除 Jetson 文件。
8. 切换网关地址并重新连接，命令区必须重新加载对应 Jetson 的记录，旧目录和白名单不能沿用。
9. 断网时显示状态读取失败并禁止启动/停止；恢复网络后自动更新真实状态。

自动检查：`npx tsc --noEmit`、`npm run lint`、`node --test frameBuffer.test.cjs latency.test.cjs ui/image-geometry.test.cjs`、`python3 -m unittest discover -s gateway -p 'test_*.py' -v`。
